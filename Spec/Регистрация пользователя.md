# Спецификация: Регистрация и профиль пользователя

**Статус:** код написан и проверен локально, не влит; нужен домен для писем и переключение базы (§19) · **Дата:** 01.11.2026 · **Связано с:** [Spec - Student cabinet and teacher notes.md](Spec%20-%20Student%20cabinet%20and%20teacher%20notes.md), [design_system.md](design_system.md)

## 1. Цель

Заменить три жёстко заданных профиля настоящими аккаунтами:

1. Ученик сам регистрируется по e-mail и паролю, подтверждает почту и входит с любого устройства.
2. Всё, что он сделал, хранится на сервере и привязано к его аккаунту.
3. Кто ты, определяет только сессия на сервере. Адрес страницы на это не влияет.
4. Учитель видит только тех учеников, которые сами присоединились к его классу.
5. Пользователь управляет своими данными: меняет имя, почту и пароль, скачивает данные, удаляет аккаунт.

**SSO нет:** ни Google, ни Apple, ни других внешних провайдеров. Единственный способ входа — e-mail и пароль.

### Как эта спека соотносится со спекой кабинета

Здесь заменяется вход по коду и уточняется кабинет. Заметки учителя остаются как есть, меняется только проверка доступа к ним.

| Спека кабинета | Что с этим теперь |
|---|---|
| §8.1 и вопрос 2 в §11: вход по коду доступа | Заменено на e-mail и пароль (§3) |
| §8.2, §8.3, §8.5: таблицы, API, перенос прогресса | Заменено на §8, §9 и §12 этой спеки |
| Этап 2 (вход и сессии) | Заменено |
| Этап 3 (прогресс на сервере) | Заменено на §12. Без него аккаунт не имеет смысла: прогресс остался бы в одном браузере |
| Шаги 4.1–4.3 (профиль) | Заменено на §6 |
| Шаги 4.4–4.5 (журнал занятий) | Остаются там, эта спека их не трогает |
| Шаг 7.4 (выдать коды) | Заменено на §5.8 |
| §8.4: защита заметок | Остаётся в силе, кроме условия, что браузер ученика не обращается к `/api/me` (§7.3) |

## 3. Решения

| # | Вопрос | Решение | Почему |
|---|---|---|---|
| 1 | Кто может зарегистрироваться | Любой, сам, как ученик | «Полноценная регистрация» |
| 2 | Как стать учителем | Только скриптом на сервере. Роль никогда не приходит из запроса | Иначе любой получит доступ к ученикам |
| 3 | Вход | E-mail и пароль, без SSO | Требование |
| 4 | Подтверждение почты | Обязательно: без него нельзя войти | Сброс пароля работает только с настоящей почтой |
| 5 | Кого видит учитель | Только учеников, присоединившихся по ссылке-приглашению | При открытой регистрации незнакомые люди иначе попали бы в класс |
| 6 | Ученик без учителя | Занимается сам, всё доступно | Приглашение необязательно |
| 7 | Контент без входа | Закрыт: без сессии виден только экран входа и регистрации | Весь контент завязан на прогресс. См. вопрос 2 в §17 |
| 8 | Идентификатор пользователя | UUID. У `maria`, `evgeny`, `teacher` остаются старые | На них уже ссылаются заметки |
| 9 | Адрес страницы | Без профиля: `#czlowiek/slownictwo`, `#dashboard` | Адрес не определяет пользователя; ссылка для домашки одна на всех |
| 10 | Переключатель профилей | Удаляется совсем, в том числе в разработке | Для проверки есть тестовые аккаунты |
| 11 | Письма | Resend, запросы через `fetch`, без SDK | Просто и подключается через Vercel. Нужен свой домен (§10.1) |
| 12 | Новые зависимости | Без библиотек авторизации и ORM | Вся криптография есть в `node:crypto`, форм мало |

| Действие | Гость | Ученик | Учитель |

| Занятия, справочник | ❌ | ✅ | ✅ (его ответы на сервер не сохраняются) |
| Видеть и менять свой профиль | — | ✅ | ✅ |
| Менять имя, почту, пароль | — | ✅ только свои | ✅ только свои |
| Менять цель, уровень, дату экзамена | — | ✅ свои | ✅ у своих учеников |
| Видеть прогресс и ответы | — | ✅ свои | ✅ своих учеников |

| Видеть заметки об ученике | — | ❌ | ✅ о своих учениках |
| Выйти из класса | — | ✅ | — |
| Убрать ученика из класса | — | — | ✅ |
| Удалить аккаунт | — | ✅ | ❌ только скриптом |

Правило для запросов к чужим данным: если ученик не связан с этим учителем или данные чужие, сервер отвечает `404`, как и для заметок сейчас. Ответ не должен подтверждать, что такой пользователь существует.

## 5. Сценарии

### 5.1. Регистрация

Адрес `#register`.

Поля: **Imię** (1–60 символов), **E-mail**, **Hasło** (показать/скрыть) и обязательная галочка «Mam ukończone 16 lat i akceptuję Regulamin oraz Politykę prywatności». Второго поля для пароля нет: вместо него кнопка показа.

После отправки всегда показывается один и тот же экран «Sprawdź skrzynkę», что бы ни произошло на сервере:

| Что с адресом | Что делает сервер |
|---|---|
| Новый | Создаёт аккаунт без подтверждения, шлёт письмо «Potwierdź e-mail» |
| Есть, не подтверждён | Заменяет имя и пароль, отменяет старые ссылки, шлёт новое письмо |
| Есть, подтверждён | Ничего не меняет, шлёт письмо «Masz już konto» со ссылкой на вход и сброс пароля |

Так по форме нельзя узнать, зарегистрирован ли адрес. Если адрес введён с ошибкой, пользователь просто регистрируется ещё раз.

На экране «Sprawdź skrzynkę» есть кнопка «Wyślij ponownie», доступная раз в 60 секунд, и подсказка про спам.

Неподтверждённые аккаунты удаляются через 7 дней. Удаление идёт при каждой новой регистрации, отдельный cron не нужен: так же уже чистятся сессии в `createSession`.

### 5.2. Подтверждение почты

1. Ссылка из письма ведёт на `#verify/<token>`, действует 24 часа, работает один раз.
2. Страница сама отправляет `POST /api/verify-email`. Письмо не должно подтверждать что-либо простым `GET`: почтовые сканеры открывают ссылки и истратили бы токен.
3. Успех: создаётся сессия, токен убирается из адреса, открывается шаг из §5.5.
4. Токен истёк или использован: «Link wygasł lub został już użyty» и кнопка «Wyślij nowy link» с полем для почты.

### 5.3. Вход

Адрес `#login`. Поля: **E-mail**, **Hasło**, ссылка «Nie pamiętasz hasła?».

- Неверная почта или пароль — один текст «Nieprawidłowy e-mail lub hasło.»
- Пароль верный, почта не подтверждена: «Potwierdź e-mail» и кнопка повторной отправки. Этот текст показывается только после проверки пароля, иначе он выдаёт, что адрес есть в базе.
- Сессия на 90 дней. Если до конца осталось меньше 30 дней, она продлевается при запросе к `/api/me`: подготовка к матуре идёт месяцами.
- После входа открывается страница, с которой человек пришёл. Адрес хранится в `sessionStorage` (`matura.returnTo`), поэтому ссылка на домашнее задание ведёт к заданию, а не на панель.

### 5.4. Забыли пароль

1. `#forgot`, поле **E-mail**. Ответ всегда «Jeśli konto istnieje, wysłaliśmy link do zmiany hasła.»
2. Ссылка `#reset/<token>` действует 1 час, работает один раз. Токен в части адреса после `#` не попадает в логи сервера.
3. Новый пароль. Успех: все сессии пользователя удаляются, создаётся новая, открывается панель. Почта при этом считается подтверждённой: письмо до него дошло.

### 5.5. Первый вход

Один необязательный экран «Uzupełnij profil», кнопка «Pomiń» его пропускает:

- **Kiedy piszesz maturę?** — дата;
- **Poziom** — `podstawowa` / `rozszerzona`;
- **Twój cel** — до 120 символов.

Экран показывается один раз (`onboarded_at`). Если есть прогресс в этом браузере, сразу после него идёт предложение из §12.4.

Если `terms_accepted_at` пуст (аккаунты из §5.8), перед этим экраном показывается принятие условий; без него работать нельзя.

### 5.6. Присоединение к классу

Учитель копирует ссылку `#join/<code>` на странице класса. Одна ссылка на класс, многоразовая. Кнопка «Nowy link» заменяет код, старая ссылка перестаёт работать, а уже присоединившихся это не затрагивает.

| Кто открыл | Что происходит |
|---|---|
| Гость | Регистрация с плашкой «Dołączasz do klasy: {teacher}». Код отправляется вместе с регистрацией и хранится на сервере: подтвердить почту можно на другом устройстве |
| Гость, уже есть аккаунт | Со страницы регистрации уходит на вход, код сохраняется в `sessionStorage` и после входа открывается экран ниже |
| Ученик | Экран «Nauczyciel {teacher} zaprasza Cię do klasy» с кнопками «Dołącz» и «Nie teraz» |
| Учитель | Текст «To jest link dla uczniów» |
| Неверный код | Текст «Ten link nie działa. Poproś nauczyciela o nowy.» |

На экране приглашения и на регистрации по приглашению обязательно указано: **«Nauczyciel zobaczy Twoje imię, e-mail, postępy i odpowiedzi w zadaniach.»** Без явного действия ученика связь не создаётся.

Ссылки на задания из «Kopiuj link» в класс не добавляют, это другие ссылки.

**Выход из класса.** Ученик нажимает «Opuść klasę» в профиле, учитель — «Usuń z klasy» на странице ученика. Связь удаляется, учитель сразу теряет доступ. Заметки остаются в базе, но API отдаёт по ним `404`; при повторном присоединении они снова видны учителю. Срок хранения — вопрос 5 в §17. Текст для ученика не упоминает заметки.

### 5.7. Выход

- «Wyloguj» в меню пользователя удаляет сессию и локальные данные (§12.3).
- Перед выходом клиент отправляет несохранённые изменения. Не получилось: диалог «Część pracy nie została zapisana. Wylogować mimo to?»
- Истёкшая сессия: при первом `401` пользователь попадает на вход с текстом «Sesja wygasła. Zaloguj się ponownie», текущий адрес сохраняется, несохранённое остаётся локально и отправляется после входа.

### 5.8. Перенос Maria, Evgeny и учителя

Скрипт `npm run user:create -- <id> <email> "<имя>" [--role teacher] [--student-of teacher]`:

1. Создаёт или обновляет запись с этим `id`, поэтому заметки об ученике не теряются. Почта считается подтверждённой.
2. Для ученика создаёт связь с учителем.
3. Шлёт письмо «Ustaw hasło» со ссылкой на `#reset/<token>`, действует 72 часа.

После этого код доступа удаляется: столбец `access_code_hash` и [teacher-code.mjs](../app/scripts/teacher-code.mjs).

## 6. Страница профиля

Адрес `#profile`, вход через меню пользователя в шапке («Mój profil»). Одна страница с блоками, у каждого своя кнопка «Zapisz».

| Блок | Содержимое | Поведение |
|---|---|---|
| **Dane** | Имя, инициалы в аватаре | Инициалы считаются сами: первые буквы первого и последнего слова имени. Загрузки фото нет |
| **Matura** | Дата экзамена, уровень, цель | Счётчик «do matury N dni» в кабинете |
| **Ustawienia** | Язык интерфейса, язык перевода | Хранятся в аккаунте, применяются при входе на любом устройстве |
| **Konto** | Почта, пароль, «Wyloguj ze wszystkich urządzeń» | См. ниже |
| **Nauczyciel** | Имя учителя и «Opuść klasę» либо подсказка, как присоединиться | Только для ученика. Текст не упоминает заметки |
| **Twoje dane** | «Pobierz moje dane», «Usuń konto» | §13 |

**Смена почты.** Нужен текущий пароль. На новый адрес уходит ссылка на 24 часа, на старый — уведомление «Adres e-mail konta jest zmieniany». Адрес меняется только после перехода по ссылке, все остальные сессии удаляются. Если новый адрес занят, письмо на него сообщает об этом, а интерфейс показывает обычный текст «Wysłaliśmy link»: так адрес нельзя проверить.

**Смена пароля.** Нужен текущий пароль. Все остальные сессии удаляются, текущая остаётся.

**Удаление аккаунта.** Отдельный диалог с вводом пароля и списком того, что удалится. Возврата нет. Письмо «Konto usunięte» уходит на почту.

Учителю на странице ученика доступны только блок **Matura** и почта для чтения.

## 7. Адреса и каркас приложения

### 7.1. Адреса

| Адрес | Страница |
|---|---|
| `#dashboard` | Кабинет ученика или класс учителя |
| `#dashboard/<studentId>` | Ученик глазами учителя |
| `#<moduleId>/<section>[/<item>]` | Занятия, как сейчас |
| `#profile` | Профиль |
| `#login`, `#register`, `#forgot`, `#regulamin`, `#prywatnosc` | Открытые экраны |
| `#verify/<token>`, `#reset/<token>`, `#join/<code>` | Переходы из писем и приглашений |

**Старые ссылки.** Если первый сегмент — `maria`, `evgeny` или `teacher`, он отбрасывается, а остальной адрес работает: `#maria/czlowiek/slownictwo` → `#czlowiek/slownictwo`. Этот короткий список остаётся в [userRoute.ts](../app/src/userRoute.ts) только ради старых ссылок. Параметр `?user=` убирается.

**Учитель на несуществующем или чужом ученике.** `#dashboard/<id>` проверяется запросом к серверу, а не по списку на клиенте; при `404` открывается класс. Ученику лишний сегмент обрезается, как сейчас.

### 7.2. Состояния приложения

Новый компонент `AuthGate` стоит над `ProgressProvider` и `App`:

| Ответ `/api/me` | Что показывать |
|---|---|
| Идёт запрос | Заглушка с логотипом |
| `200` | Приложение. `user` дальше никогда не `null` |
| `401` | Экраны входа и регистрации, адрес сохраняется в `returnTo` |
| Сеть или `5xx` | «Nie udało się połączyć» и «Spróbuj ponownie». **Не экран входа:** пропавшая сеть не должна выглядеть как разлогин |

`UserProvider` получает данные из `/api/me`. Хук `useUser()` сохраняет поле `user`, поэтому его потребителей менять почти не нужно. `users`, `setUserId`, `findUser`, `DEFAULT_USER_ID` и файл [users.ts](../app/src/users.ts) в его нынешнем виде исчезают; остаются типы и подписи ролей.

Экраны входа не должны попадать внутрь `App`: у них нет боковой панели и шапки с меню.

### 7.3. Шапка и код учителя

- Вместо переключателя — меню с именем, почтой, «Mój profil», «Wyloguj».
- `useTeacherSession` и `TeacherAccess` удаляются: сессия теперь одна на всех, вход отдельный.
- `TeacherStudentPage` и `TeacherClassPage` по-прежнему загружаются через `React.lazy` и только при `role === 'teacher'`.
- Браузер ученика теперь обращается к `/api/me`. Это допустимо: ответ не содержит ничего о заметках (§8.4 спеки кабинета, п. 2).

### 9.4. Общие проверки

В [http.ts](../app/api/_lib/http.ts) вместо `isTeacher()`:

```ts
getSessionUser(req): Promise<{ id: string; role: UserRole } | null>
requireUser(req)            // нет сессии → 401
requireTeacher(req)         // не учитель → 404
requireStudentOf(req, id)   // учитель и есть запись в teacher_students, иначе 404
```

Проверка на чтение и на запись одинаковая, идентификатор пользователя берётся только из сессии. Запросы ученика не содержат чужого `id`: маршруты вида `/api/progress` работают с пользователем сессии, поэтому подставить чужой идентификатор негде.

## 10. Письма

### 10.1. Что нужно до начала работы

**Нужен свой домен.** С адреса `*.vercel.app` письма слать нельзя, а тестовый отправитель Resend доставляет только на почту владельца аккаунта Resend. На домене настраиваются SPF и DKIM, иначе письма пойдут в спам.

Переменные окружения: `RESEND_API_KEY`, `MAIL_FROM` (`Matura English <noreply@…>`), `APP_URL`.

**Ссылки в письмах строятся только из `APP_URL`,** а не из заголовка `Host`: иначе подменённый заголовок отправит токен на чужой сайт.

При локальной разработке без ключа письмо выводится в консоль. Вне локальной разработки такой режим недоступен: без ключа функция завершается ошибкой, а токены в лог не попадают.

### 10.2. Перечень

Письма простые: текст и одна кнопка. Язык — `ui_lang` аккаунта, для неизвестного адреса — язык формы.

| Письмо | Тема (pl) | Срок ссылки |
|---|---|---|
| Подтверждение почты | Potwierdź swój e-mail | 24 ч |
| Адрес уже занят | Masz już konto | — |
| Сброс пароля | Zmiana hasła | 1 ч |
| Новый аккаунт (§5.8) | Ustaw hasło | 72 ч |
| Смена почты (на новый адрес) | Potwierdź nowy e-mail | 24 ч |
| Смена почты (на старый адрес) | Zmiana adresu e-mail | — |
| Пароль изменён | Hasło zostało zmienione | — |
| Аккаунт удалён | Konto usunięte | — |

Письма о смене пароля и почты содержат текст «Jeśli to nie Ty, zmień hasło i napisz do nas» и адрес для связи.

## 11. Безопасность

### Пароли

- Длина 10–128 символов. Требований к составу нет. Отклоняются пароли из короткого списка самых частых и совпадающие с почтой.
- `scrypt` с солью. Параметры `N=2^17, r=8, p=1`; сейчас в [accessCode.ts](../app/api/_lib/accessCode.ts) значения по умолчанию, `N=2^14`. Для такого `N` нужно поднять `maxmem`. Параметры хранятся в самом хэше, чтобы их можно было усилить позже: `scrypt$17$8$1$<salt>$<key>`.
- Файл переименовывается в `_lib/password.ts`, `normalizeCode` и `generateCode` удаляются: пароль, в отличие от кода, чувствителен к регистру.

### Что нельзя выдать

- Форма регистрации, вход и сброс не должны показывать, есть ли адрес в базе (§5.1, §5.3, §5.4).
- При входе с неизвестным адресом всё равно считается `scrypt` с пустышкой. Иначе ответ придёт заметно быстрее.
- Письма отправляются после ответа клиенту (`waitUntil`), чтобы время ответа не зависело от того, было ли что отправлять.

### Лимиты

Все хранятся в `rate_limits`, ответ `429`.

| Действие | Лимит |
|---|---|
| Неудачный вход с парой «адрес + IP» | 5 за 15 минут |
| Неудачный вход с одного IP | 100 за 15 минут (школа за одним IP) |
| Регистрация с одного IP | 20 за час |
| Письма на один адрес | 3 за час, сверх лимита молча не отправляются |
| Токены `verify` и `reset` с одного IP | 20 за 15 минут |

Лимит «письма на адрес» защищает от рассылки на чужую почту через нашу форму. В форме регистрации есть скрытое поле-ловушка для ботов. Капчи пока нет: добавим, если появятся боты.

### Сессии и запросы

- Cookie как сейчас: `HttpOnly; Secure; SameSite=Lax; Path=/api`.
- Все сессии удаляются при сбросе пароля и удалении аккаунта; все, кроме текущей, — при смене пароля или почты.
- Запросы с методами `POST`, `PUT`, `PATCH`, `DELETE` отклоняются, если заголовок `Origin` не совпадает с адресом сайта.
- Поля `role`, `email_verified_at`, `invite_code` нельзя изменить через `PATCH`: сервер принимает только перечисленные поля.
- В логи не попадают пароли, токены, почта и текст заметок. `guarded()` уже пишет только код ошибки.

## 12. Прогресс на сервере

### 12.1. Хранение

Одна строка на пользователя и модуль, `data` — объект `ModuleProgress` из [progress-context.ts](../app/src/progress-context.ts). Таблица со столбцами из §8.2 спеки кабинета больше не подходит: с тех пор в прогресс добавились `testWork`, `gapWork`, `pictureNotes`, `essay`.

Сервер проверяет: `moduleId` из 14 модулей, размер тела до 256 КБ, форма совпадает с `ModuleProgress`. Без этого ученик мог бы записать в базу что угодно, а учитель это потом открыл бы.

### 12.2. Сохранение

Внешний API `ProgressProvider` остаётся прежним, меняется только его внутренняя часть:

- при входе загружается весь прогресс; учителю — `GET /api/class`;
- изменение сразу применяется на экране и пишется в локальную копию;
- через 1,5 секунды после последнего изменения изменённые модули отправляются на сервер;
- при ошибке — повтор с нарастающей паузой и снова при возвращении сети;
- `saveFailed` теперь означает «не удалось сохранить на сервере»; [SaveStatus.tsx](../app/src/components/SaveStatus.tsx) показывает это как сейчас.

**Конфликт двух устройств.** Побеждает последняя запись по модулю. Чтобы данные не перезаписывались старой копией, при возвращении на вкладку прогресс загружается заново, если нет неотправленных изменений. Посимвольного слияния нет.

### 12.3. Локальная копия

Ключ `matura.progress.cache.<userId>`, отдельно для каждого аккаунта. **При выходе ключ удаляется:** компьютер может быть школьным, а там сочинения ученика. Ключ `matura.currentUser` удаляется совсем.

### 12.4. Перенос из браузера

После входа, если в `matura.progress.v3` есть данные для `id` этого пользователя, а на сервере прогресс пуст: «Znaleźliśmy postęp zapisany w tej przeglądarce. Przenieść go na konto?». Да — данные загружаются, ключ удаляется; нет — ключ удаляется.

Это касается только Maria и Evgeny: новые аккаунты имеют UUID и совпасть не могут. Поэтому слияния нет: если на сервере прогресс уже есть, предложение не показывается.

## 15. Критерии приёмки

**Регистрация и вход**

1. Новый пользователь регистрируется, получает письмо, подтверждает почту и попадает в свой пустой кабинет.
2. Без подтверждения войти нельзя; пароль верный — показана кнопка повторной отправки, неверный — общий текст ошибки.
3. Ответ формы регистрации одинаков для нового и уже существующего адреса; на существующий уходит письмо «Masz już konto», пароль не меняется.
4. Ссылка подтверждения или сброса не срабатывает второй раз и после истечения срока.
5. Сброс пароля завершает сессии на других устройствах.
6. Шесть неверных паролей подряд дают `429`; с другого IP вход работает.
7. Ссылка на задание, открытая без сессии, после входа ведёт на это задание.
8. Старая ссылка `#maria/czlowiek/slownictwo` открывает задание в профиле вошедшего, а не Maria.

**Профиль**

9. Изменения имени, языка, даты экзамена сохраняются и видны на другом устройстве.
10. Смена почты работает только после перехода по ссылке с нового адреса; на старый приходит уведомление.
11. Удаление аккаунта убирает из базы пользователя, прогресс и заметки о нём; войти больше нельзя.
12. В выгрузке данных есть профиль и прогресс.

**Права**

13. Ученик запрашивает прогресс другого ученика, `GET /api/students/<id>` или заметки — ответ `404`.
14. Подмена `role` в `PATCH /api/me` не меняет роль.
15. Новый зарегистрированный ученик не виден учителю, пока не нажмёт «Dołącz» на странице приглашения.
16. После «Opuść klasę» или «Usuń z klasy» учитель получает `404` на прогресс и заметки этого ученика, а при возвращении ученика видит их снова.
17. Maria и Evgeny после переноса видят свой прогресс и входят своим паролем; заметки о них на месте.
18. Код панели заметок не загружается в браузере ученика; в ответах API ученику нет ни слова о заметках.

**Данные на устройстве**

19. Прогресс, начатый на телефоне, виден на компьютере после перезагрузки.
20. После «Wyloguj» в `localStorage` нет данных ученика; второй человек на том же компьютере их не видит.
21. Отключение сети не показывает экран входа; работа сохраняется после возвращения сети.
22. Учитель видит настоящий прогресс ученика, который занимался на своём устройстве.

**Интерфейс**

23. Все экраны работают на 360 px; менеджер паролей предлагает сохранить пароль при регистрации.
24. Все новые строки есть на польском и английском.

## 19. Как сделано (01.11.2026)

Отличия от спеки выше:

- **Маршруты API сгруппированы в 11 файлов.** Каждый файл в `app/api` — отдельная функция, а на тарифе Hobby их не больше 12. Поэтому вход живёт в `/api/auth?action=…`, аккаунт в `/api/account?action=…`, приглашения в `/api/class` и `/api/auth?invite=…`. `DELETE /api/progress` не понадобился: очистка своего прогресса уходит обычным сохранением модулей.
- **В прогрессе хранится `{ module, cards }`.** После этой спеки в `ProgressState` появились свои карточки ученика, а `lastModuleId` и `lastDeckId` лежат в `users.progress_meta`.
- **Карточки учителя тоже закрыты.** `GET /api/students/:id/cards` раньше работал без сессии; теперь он доступен только самому ученику и его учителю. `user_cards` получила внешний ключ с каскадом.
- **`user:create` печатает ссылку на установку пароля, а не отправляет письмо.** Так перенос Maria, Evgeny и учителя не зависит от домена.
- **Блока «Ustawienia» в профиле нет.** Языки уже меняются в меню настроек в шапке и оттуда сохраняются в аккаунт.
- **Учитель меняет план ученика во вкладке «Matura»** на странице ученика; там же «Usuń z klasy».
- **Диалоги подтверждения — `window.confirm`,** как у «Wyczyść postęp».
- **Страницы `#regulamin` и `#prywatnosc` — заглушки:** тексты должны прийти от владельца.

### Что осталось

1. Домен, Resend и переменные окружения (шаги 1.1, 1.2). Без них на Vercel письма не уходят, а регистрация не завершается.
2. Переключение базы (шаг 4.6) — в момент вливания: `npm run db:migrate` удаляет `access_code_hash` и `login_attempts`, и до этого момента старая версия сайта ещё работает. Затем `npm run user:create` для учителя, Maria и Evgeny.
3. Тексты Regulamin и Polityka prywatności (шаги 0.2, 7.8), вопросы 1, 3 и 4 из §17, проверка регионов (шаг 0.3).
4. Шаги 8.1–8.3 на Preview. Локально проверены API и основные сценарии в браузере; не проверены доставка настоящих писем, перенос из `matura.progress.v3` и экраны смены почты и удаления аккаунта в браузере (их API проверено).
